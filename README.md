# AiNewsPulses

ایجنت خودکار خبر هوش مصنوعی، فناوری، برنامه‌نویسی و علم داده برای کانال تلگرام `@AiNewsPulses`.
خبرها را از منابع معتبر می‌گیرد، متن واقعی مقاله را می‌خواند، با Gemini پست فارسی می‌نویسد، خروجی را اعتبارسنجی می‌کند و (فقط وقتی صراحتاً روشن شده باشد) در تلگرام منتشر می‌کند. اجرای نهایی روی GitHub Actions است.

> **وضعیت پیش‌فرض: انتشار خاموش است.** تا وقتی `ENABLE_PUBLISHING=true` را خودتان تنظیم نکنید، هیچ پیامی به تلگرام نمی‌رود.

## قابلیت‌ها
- جمع‌آوری از RSS/Atom؛ خرابی یک منبع بقیه را متوقف نمی‌کند.
- استخراج متن واقعی مقاله (`trafilatura` + جایگزین `BeautifulSoup`). هیچ خبری فقط از روی عنوان نوشته نمی‌شود.
- امتیازدهی قابل‌توضیح ۰ تا ۱۰۰ (اعتبار منبع، تازگی، اهمیت، ارتباط، شواهد، تصویر) با وزن‌های تنظیم‌پذیر؛ زیر ۶۵ رد می‌شود و علت در لاگ ثبت می‌شود.
- تولید پست فارسی فقط از روی شواهد مقاله؛ ورودی وب «داده» است نه «دستور» (خطوط شبیه prompt-injection حذف می‌شوند).
- اعتبارسنجی خروجی: هشتگ، عنوان، لینک منبع عیناً، آیدی کانال، طول، فارسی بودن، نبود Markdown، نبود نقل‌قول مستقیم، و **هر عدد ≥۲ رقمی باید در متن منبع وجود داشته باشد** (جلوگیری از آمار ساختگی).
- جلوگیری از تکرار با SQLite (نرمال‌سازی URL + تشخیص عنوان مشابه).
- سقف ۴ پست در روز به وقت تهران، کنترل‌شده در برنامه (نه فقط با تعداد اجراها).
- حالت `--dry-run`، لاگ بدون Secret، تست‌های خودکار.

## معماری و جریان اجرا
```
sources → collector → deduplicator → ranker(پیش‌امتیاز) → extractor → ranker(نهایی)
        → validator(شواهد) → writer(Gemini) → validator(پست) → publisher → database
```
| فایل | مسئولیت |
|---|---|
| `main.py` | هماهنگی کل جریان، `--dry-run` |
| `config.py` | تنظیمات محیطی و پیش‌فرض‌های امن |
| `sources.py` | فهرست منابع (تنها جای افزودن/حذف منبع) |
| `collector.py` | دریافت و پارس RSS/Atom |
| `extractor.py` | استخراج متن مقاله و تصویر شاخص |
| `validator.py` | کفایت شواهد، پاک‌سازی ورودی، اعتبارسنجی پست |
| `deduplicator.py` | نرمال‌سازی URL و حذف تکراری |
| `ranker.py` | امتیازدهی، دسته‌بندی (هشتگ) |
| `writer.py` | Gemini؛ قالب نهایی پست را خود برنامه می‌سازد |
| `image_handler.py` | بررسی تصویر و مجوز (پیش‌فرض خاموش) |
| `publisher.py` | ارسال امن به Telegram Bot API |
| `database.py` | SQLite و وضعیت هر خبر |
| `scheduler.py` | سقف روزانه به وقت تهران |
| `logger.py` | لاگ ساختاریافته با حذف خودکار Secretها |
| `netutils.py` / `models.py` | دریافت امن از وب / مدل‌های داده |
| `scripts/check_feeds.py` | بررسی زنده‌ی فیدها |

وضعیت‌های خبر: `discovered → extracted → drafted → publishing → published` و شاخه‌های `rejected` و `failed`.

## پیش‌نیازها
- Python 3.11+ ، یک مخزن **خصوصی** GitHub
- ربات تلگرام (از BotFather) که **ادمین کانال** با دسترسی ارسال پیام باشد
- کلید Gemini API (Google AI Studio)

## راه‌اندازی محلی
```bash
python -m venv .venv && source .venv/bin/activate      # ویندوز: .venv\Scripts\activate
pip install -r requirements-dev.txt
cp .env.example .env                                    # GEMINI_API_KEY را پر کنید
python -m pytest -q                                     # تست‌ها (بدون اینترنت)
python scripts/check_feeds.py                           # بررسی زنده‌ی فیدها (اینترنت لازم است)
python main.py --dry-run                                # اجرای کامل بدون ارسال و بدون تغییر پایگاه داده
```
در `--dry-run` پیش‌نویس‌ها در لاگ چاپ می‌شوند. پایگاه داده‌ی واقعی دست نمی‌خورد (روی کپی موقت کار می‌شود).

## راه‌اندازی GitHub Actions
۱. در **Settings → Secrets and variables → Actions → Secrets** بسازید: `GEMINI_API_KEY` و `TELEGRAM_BOT_TOKEN`.
۲. (اختیاری) در **Variables**: `GEMINI_MODEL`، `TELEGRAM_CHANNEL_ID`، `MIN_QUALITY_SCORE` و ...
۳. در **Settings → Actions → General → Workflow permissions** مقدار *Read and write* را بگذارید (برای commit پایگاه داده).
۴. ابتدا از تب Actions با **Run workflow** و `dry_run=true` اجرا کنید و پیش‌نویس‌ها را در لاگ بخوانید.
۵. فقط وقتی از کیفیت راضی بودید: Variable با نام `ENABLE_PUBLISHING` و مقدار `true` بسازید. برگشت: مقدار را `false` کنید.

## زمان‌بندی
تهران UTC+03:30 است (ساعت تابستانی ندارد). cron گیت‌هاب UTC است:

| تهران | UTC |
|---|---|
| 09:00 | 05:30 |
| 13:00 | 09:30 |
| 17:00 | 13:30 |
| 21:00 | 17:30 |

عبارت cron: `30 5,9,13,17 * * *`. هر اجرا حداکثر یک خبر منتشر می‌کند (`MAX_POSTS_PER_RUN`). سقف روزانه (`DAILY_POST_LIMIT`، حداکثر ۴) از روی SQLite و با «روز تهران» کنترل می‌شود؛ اجرای دستی هم نمی‌تواند آن را دور بزند. GitHub گاهی اجراها را با تأخیر می‌زند.

## تنظیمات
نام و مقدار پیش‌فرض همه‌ی متغیرها در `.env.example` است. وزن امتیازها با `SCORE_WEIGHTS` (JSON، مثلاً `{"freshness": 25}`) قابل تغییر است. `DAILY_POST_LIMIT` هرچه باشد از ۴ بیشتر نمی‌شود.
`GEMINI_MODEL` پیش‌فرض `gemini-2.5-flash` است؛ اگر در حساب شما نام دیگری معتبر است همین متغیر را عوض کنید.

## منابع
فقط `sources.py` را ویرایش کنید (نام، آدرس، نوع `official/media/tutorial`، دسته، اعتبار، `enabled`). آدرس فیدها از محیط ساخت راستی‌آزمایی نشده‌اند؛ **قبل از اولین اجرا `scripts/check_feeds.py` را بزنید.** برای Anthropic و Meta AI فید RSS رسمی شناخته‌شده‌ای نداشتم؛ غیرفعال گذاشته شده‌اند. آموزش‌ها با هشتگ `#آموزش` و نوع `tutorial` از خبر جدا می‌مانند.

## تصویر
پیش‌فرض خاموش. وجود `og:image` مجوز بازنشر نیست؛ حتی با `ALLOW_ARTICLE_IMAGES=true` فقط تصویر دامنه‌هایی استفاده می‌شود که در `IMAGE_ALLOWED_DOMAINS` بیاورید (یعنی خودتان مجوز را بررسی کرده‌اید). تصویر با کنترل نوع و حجم دریافت می‌شود و نبود تصویر هرگز مانع انتشار خبر نیست.

## رفتار در خطاها (تصمیم‌های مهم)
- **ارسال با وضعیت نامعلوم** (timeout خواندن، خطای 5xx، قطع اتصال وسط کار): خبر در وضعیت `publishing` می‌ماند، **هرگز خودکار دوباره ارسال نمی‌شود**، در سقف روزانه شمرده می‌شود و اجرا متوقف می‌شود. لاگ هشدار می‌دهد؛ کانال را دستی چک کنید و در صورت لزوم وضعیت را در پایگاه داده اصلاح کنید.
- **سهمیه‌ی Gemini تمام شد:** اجرا بدون انتشار پایان می‌یابد؛ پست بی‌کیفیت ساخته نمی‌شود.
- **خطای دائمی تلگرام** (مثلاً ربات ادمین کانال نیست): خبر `failed` می‌شود و اجرا متوقف می‌شود. هر خبر حداکثر ۳ بار تلاش می‌شود.
- **خطای Git push:** هرگز پایگاه داده بی‌بررسی بازنویسی نمی‌شود؛ workflow با خطا تمام می‌شود.

## محدودیت‌های نگهداری SQLite در GitHub
- فقط یک اجرا همزمان مجاز است (`concurrency`) و تغییرات هر اجرا commit می‌شود.
- اگر پس از انتشار، push پایگاه داده شکست بخورد، اجرای بعدی از آن انتشار خبر ندارد و ممکن است همان خبر را دوباره بفرستد. اگر workflow در مرحله‌ی «Commit database» خطا داد، سریع بررسی کنید.
- با هر اجرا یک commit باینری ساخته می‌شود و تاریخچه‌ی مخزن بزرگ می‌شود. مخزن باید **خصوصی** بماند.
- مناسب پروژه‌ی کوچک است. `database.py` تنها لایه‌ی دسترسی است و می‌توان بعداً آن را با PostgreSQL عوض کرد.
- cache گیت‌هاب برای نگهداری دائمی استفاده نشده است.

## تست‌ها
`python -m pytest -q` — بدون اینترنت و بدون اعتبارنامه‌ی واقعی؛ همه‌ی تماس‌های شبکه mock هستند و یک fixture خودکار هر اتصال واقعی را مسدود می‌کند (پس هیچ تستی به کانال واقعی پیام نمی‌فرستد). پوشش: RSS سالم/خراب، تکراری‌ها، رد خبر بدون شواهد، امتیازدهی، اعتبارسنجی پست (لینک، آیدی، طول، هشتگ، عدد ساختگی)، SQLite، سقف روزانه، dry-run، خاموش بودن انتشار، خطای Gemini و Telegram، اجرای مجدد، نبود Secret در لاگ و پایگاه داده، نبود خبر مناسب.

## عیب‌یابی
| نشانه | علت/راه‌حل |
|---|---|
| `chat not found` / `forbidden` | ربات ادمین کانال نیست یا `TELEGRAM_CHANNEL_ID` اشتباه است |
| `Gemini request rejected (400/403/404)` | کلید یا `GEMINI_MODEL` نامعتبر است |
| `quota exhausted` | سهمیه‌ی Gemini تمام شده؛ اجرای بعد دوباره تلاش می‌کند |
| `no suitable news found` | طبیعی است؛ خبر مناسب نبود و چیزی منتشر نشد |
| `source failed: ...` | آدرس فید خراب است؛ `check_feeds.py` را اجرا کنید |
